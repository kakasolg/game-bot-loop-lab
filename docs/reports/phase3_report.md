## 4. Interpretation Limits

1. The `+2` net dev improvement (`93 -> 95 / 100`, rescuing `3, 29, 80` and eliminating all `118` blocked-`forward` steps at the cost of harming `seed 88` and leaving `15, 43, 50, 94` failing) shows what this specific DAgger-style procedure achieved for this NumPy baseline on exploratory dev seeds `0..99`. It does **not** establish the original cause of the Phase 1 failures.
2. `seeds 3` and `50` showed different responses (`3` succeeded; `50` stopped blocked-`forward` steps but entered a `2`-step turn loop). This does **not** separate extrapolation errors from memory issues or establish why `15, 43, 50, 88, 94` failed.
3. Because `3,502` automated labels came from `BabyAIBot`, low runtime (`4.97 s`) does **not** transfer as low developer/human labeling cost outside BabyAI.
4. This experiment does **not** rank retraining against execution-side recovery rules (including loop breakers for non-fixed-point cycles, which were not evaluated here), does **not** prove memory or recovery is unnecessary or necessary, and is a NumPy study rather than a Laya evaluation. Reserved confirmation seeds `30000..30199` remain untouched.
